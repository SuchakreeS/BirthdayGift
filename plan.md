# Birthday surprise site — plan.md

## What this is
A private, single-use website built as a birthday surprise for the user's girlfriend. Flow: PIN lock → hint reveal → quiz → photo album → music → reward reveal → wish input → "song's not over" interstitial → letter pages.

## Stack
- Next.js (React), single project
- No database/custom backend needed — all content is hardcoded/static, no user accounts
- **Exception:** the wish-input step (see below) submits via Formspree, a third-party form-to-email service — no server code of our own, but it is an external network call, unlike every other step.
- **animejs** (v4) — used for the reward reveal's 2D light-burst flash, the wish-input step's post-submit "Your wish shall be granted" starfield + warp-speed transition, and (as of the page-turn removal below) the shared warp transition between photo album/letter pages. (The reward reveal's box-open/ticket-spin/glitter sequence itself moved into the 3D model's own baked animation — see the three.js line below.)
- **three.js** (via `@react-three/fiber` + `@react-three/drei`) — renders the reward reveal's 3D gift-box model (`public/models/reward-box.glb`), plays its baked open/ticket-rise/spin animation clips on tap.
- Deployed on Vercel — user handles the deployment themselves, no action needed from here

## Flow (in order)
0. **Landing page** — the very first screen, before the PIN. A hanging-bunting banner ("HAPPY BIRTHDAY" on one rope, "my BELOVED" on a second rope below it) suspended from the top of the screen with a gentle sway, balloons in the theme palette (wine/gold/blush) floating upward continuously in the background, and a Thai instruction pinned to the bottom: "แตะที่ไหนก็ได้เพื่อเข้าไป". Tapping/clicking anywhere on the screen triggers a "walking closer to the sign" transition — the whole scene (banner + balloons) zooms/dollies forward (scales up, centered toward the banner) and fades out — then advances into the PIN screen.
1. **PIN screen** — she enters a 4-digit PIN. Wrong entry shakes the input and reveals one hint at a time (max 3 hints). Correct entry advances to the quiz.
1.5. **Trust-check interstitial** — brief screen right after PIN unlock, before the quiz. Two lines of Thai text, fade in staggered: "แต่ เราจะแน่ใจได้ยังไงว่าเป็นเทอจริง" then "ลองตอบคำถามมาก่อนนะ". Auto-advances into the quiz after a short delay (3s) — no tap needed, same auto-advance pattern as the "song's not over" interstitial (step 7).
2. **Quiz** — multiple-choice "about us" questions. No typing required, just tapping an option. Both the order of the questions themselves and each question's choice order are randomized/shuffled every time the quiz is opened or the page is refreshed (not a fixed order). After she taps an option, a dramatic reveal plays: wrong answers shake the screen, correct answers get a celebratory sparkle/glow effect, alongside the text "เป็นคำตอบที่ถูกต้องนะค้าบบบบ" (correct) or "เป็นคำตอบที่ยังม่ายช่ายยยย" (wrong). Wrong answers block progress — she must retry the same question until she picks correctly before advancing.
2.5. **Album intro** — brief screen right after the quiz is passed, before the photo album. Text "ใช่จริงๆด้วย อ้วนมาเร็ววว เรามีอะไรให้ดู" with a button below reading "กดเพื่อเดินเข้าไป". Tapping the button plays the same "walking closer" transition as the landing page (step 0) — reuses the shared `animate-walk-closer` effect — then advances into the photo album.
2.75. **Album reveal** — screen right after the album intro, before the actual photo album. Text "คุณได้รับอัลบัม" shows first; after a 3s delay an album graphic (CSS/SVG cover — wine + gold border with the existing infinity-knot seal as its emblem, no source image) fades in below it along with the instruction "กดเพื่อเปิดอัลบัม". Tapping anywhere once it's revealed plays the shared warp-speed transition (same effect as the album's year-to-year page flips, per user request — not the walk-closer effect used on the landing/intro screens) into the photo album itself.
3. **Photo album** — a single-page card (fixed portrait aspect ratio, capped to a max width of 560px) that advances via dedicated Back/Next buttons and a warp-speed transition (star-streak + flash, same effect as the wish-input step's transition, built as a shared `useWarpTransition` hook) — **not** StPageFlip/page-turning, which was removed after repeated flip-mechanic bugs on top of a collage-overlap bug. Hybrid mode: auto-advances on a timer but she can also tap Next/Back to go faster or slower. **One page per year** (not one page per photo): all of a year's photos appear together on that year's page in a **3-column CSS grid** (real grid, not absolute-positioned scatter slots — cells can't overlap by construction, and each photo's size is relative to its cell so it scales with however much room the page has), photos rotated slightly per-slot for scrapbook character. The year number sits in its own fixed header row at the top of the page — photos never overlap the year label. Photos are grouped by year (source folders `2022/`, `2023/`, etc. in `source_file/images/`), ordered by filename within each year. If a year has too many photos to fit well on one page (more than 8), it spills onto an additional page for that year (page 1 and 2 of that year, shown as a small "1 / 2" indicator under the year label) rather than trimming photos.
   - **Auto-flip timer (built)**: once every photo on the active page has finished flying in, the page waits 4.5s then auto-advances to the next page. She can still swipe/tap any page edge at any time to go faster/slower than the timer; a manual flip just retargets the same timer logic at the newly active page. **Does not apply to the very last page** — leaving the album for the reward reveal is a manual tap on a "Continue to your surprise →" button (appears once the last page's photos finish flying in), not an automatic timer.
   - **Entrance animation**: each time a year's page is flipped to (every time, not just first view), its photos fly in and pin themselves into their scattered collage position, slower/more deliberate than a snappy UI animation. Each photo gets a small decorative pushpin/washi-tape-corner graphic once it lands, reinforcing the scrapbook feel. Staggering is **driven by the song's actual detected beats** (see step 4) rather than a fixed timer — each successive photo flies in on the next detected beat since that page became active, so the pacing follows the music live rather than a canned delay. The first photo in a page always appears immediately on activation (doesn't wait for a beat), so the page is never empty if beat detection stalls (e.g. autoplay blocked).
4. **Music** — plays in the background starting when the album opens (real playback, not just a later add-on — pulled forward into step 3's build since the photo entrance animation needs to analyze the actual audio in real time to sync to it). Does **not** loop — plays once from the start through to its natural end. Persists across every step from the album onward (reward → wish input → song's-not-over → letter pages) — the `<audio>` element and its beat-detection logic live in a `MusicProvider` mounted once around all of those steps (see `MusicProvider.tsx`), rather than inside the album itself, so navigating between steps doesn't restart or cut off playback. Uses the Web Audio API (`AnalyserNode` on the bass frequency bins) for lightweight real-time beat/onset detection — not true music-information-retrieval beat-tracking, just energy-threshold onset detection tuned to feel right, and it works with any song without needing hand-authored timestamps. **Known limitation**: browser autoplay policies may block playback starting automatically on some devices/browsers (especially iOS Safari) despite prior user interaction earlier in the flow — needs a real-device check; if blocked, the album still works, just without music/beat-synced entrances until she interacts with the page again.
5. **Reward reveal** — a closed present box sits on screen; she taps/clicks it to open it. On tap: a warm golden shining-light burst flashes (2D, animejs), and the 3D model (`public/models/reward-box.glb`, rendered via `@react-three/fiber`) plays its own baked animation — lid opens, one ticket rises and spins around its vertical axis, settling upright — at a deliberate/unhurried pace (not snappy; the model's clips run ~4s). Once opened, gold stars gently fall in the background continuously/indefinitely for as long as she stays on the screen (ambient, not a one-off burst, separate looping CSS animation, unchanged from before). The ticket reads "บัตรตามใจ" as the title, with the subtitle "สามารถใช้บัตรใบนี้เพื่อให้เราตาใจได้ บัตรใบนี้มีผล 24 ชั่วโมง วันหมดอายุ:ไม่มี" — rendered as an HTML text overlay faded in once the 3D ticket settles (the model's ticket mesh has no baked-in texture/text), positioned/timed off the model's animation length. Text styling is open to interpretation/whatever fits the theme.
6. **Wish input** — after the reward reveal. She types a birthday wish for herself into a text box; on submit it's emailed to the user (poomfail2013@gmail.com) via Formspree. Not saved/displayed anywhere else — one-way send. After submit, an anime.js animation plays: a twinkling starfield behind the text "Your wish shall be granted", text rises in on top. After a few seconds it transitions into the "song's not over" interstitial via a **warp-speed effect**: the twinkling stars stretch into radiating streaks and rocket outward, the text zooms/fades, and a bright flash peaks — all anime.js-driven, no tap needed.
7. **"Song's not over" interstitial** — brief screen between the wish-input end screen and the letter pages. Ivory background (matches the site's main look, not the wish-input's dark end screen), continuous falling gold stars in the background (same `star-fall` pattern as the reward reveal), with the text "เพลงยังไม่จบเลย เพราะงั้นอ่านต่ออีกนิดนึงนะ". Auto-advances into the letter pages after ~4 seconds — no tap needed.
8. **Letter pages** — the true final step. Same warp-transition pager as the photo album (single-page card + Back/Next buttons + warp-speed transition, no StPageFlip), 2-3 pages with 4-5 sentences each, written by the user as a birthday message to her. Within a page, only **one sentence shows at a time**, centered in the card: it pops up small→big with a soft blur (dedicated `letter-cycle` CSS animation, 5s, appear/disappear each running at ~0.5x speed of the first pass — deliberately slower/more "romantic reveal" than the `soft-reveal` fade-in used everywhere else in the site), holds so it can be read, then shrinks back down and fades away before the next sentence takes its place — not all sentences stacked and visible together. **Once every sentence on the page has cycled through once, the full page's text fades in together** (stacked, static, reusing the shared `soft-reveal` fade with a quick per-line stagger) so she can re-read the whole message at once before moving on. The cycle (and the full-text reveal) restarts from scratch each time a page is navigated to. Navigation is manual Back/Next taps, same mechanism as the album — no auto-advance timer for *pages* (no audio to sync it to, and it's meant to be read at her own pace), though the sentence-to-sentence cycling within a page is automatic/timed. Reached via the reward reveal → wish input → "song's not over" interstitial chain. Content is the user's real birthday message (3 pages), written directly into `LetterPages.tsx`.
